# Доска задач проекта

Плагин **«Задачи»** в левой панели DSH — визуальная доска работ по проекту:
карточки, статусы, посты и отдельный чат на каждую задачу.

## Правило первое: у каждого проекта своя доска

Доска привязана к папке проекта. При первом открытии проекта плагин делает
его собственную копию задач — дальше проекты не пересекаются: изменения,
импорт и посты одного не трогают другой.

## Коды задач

Код — **не обязателен**. Если пользователь любит код, формат придумывает он
сам (`M_001`, `PRJ-1`, `шаг 3` — что угодно). Если кода нет, карточка живёт
по одному названию, и это нормально.

Агент не навязывает нумерацию и не требует её.

## Префиксы и номера

Коды — не обязательны, но если проект ведётся долго, они сильно помогают
связывать задачи с коммитами.

Правило: **один префикс на проект**, выбирается один раз в начале.

1. В главном чате предложи 2–3 варианта префикса: по инициалам проекта,
   по короткому названию, по домену (`PRJ`, `SHOP`, `AST`).
2. Спроси: оставляем осмысленный префикс или пусть номера и коды будут
   случайными от ИИ.
3. Выбор запиши в `.workspace/tasks.json` в поля `prefix` и `next`.
4. Дальше код выдаётся как `ПРЕФИКС-НОМЕР`, номер растёт по порядку.
5. Префикс проекта не меняется после первого коммита — иначе развалится
   связь задач с историей.

Если пользователь отказался от кодов совсем — не настаивай, просто оставь
поле `code` пустым.

## Формат файла

Задачи — массив объектов. Файл кладётся в проект как `.workspace/tasks.json`:

```json
{
  "prefix": "PRJ",
  "next": 4,
  "board": [
    {
      "id": "player-move",
      "code": "PRJ-1",
      "title": "Игрок и управление",
      "note": "Короткая строка для карточки",
      "desc": "Что нужно сделать, простыми словами",
      "how": "Как это делать: узлы, файлы, подход"
    }
  ]
}
```

- `id` — латиница и дефисы, уникальный в проекте, не меняется;
- `code` — по желанию;
- `note` — одна строка для карточки;
- `desc` — 1–3 предложения без технического жаргона;
- `how` — технический план: файлы, узлы, события.

## Как задача попадает на доску

Пользователь нажимает **«Импорт»** в шапке доски и выбирает файл.
Импорт заменяет список задач текущего проекта.

Алгоритм агента:

1. Обсудить, что нужно сделать.
2. Собрать массив задач по формату.
3. Записать `.workspace/tasks.json` в папку проекта.
4. Сказать: «нажми Импорт и выбери `.workspace/tasks.json`».

## Первый запуск проекта

В главном чате нового проекта сначала смотрим, что уже лежит в папке:

- папка пустая → начинаем discovery-interview;
- в папке есть файлы → читаем их, пересказываем понятое и только потом
  спрашиваем о том, чего не хватает.

## Коммиты

Чат каждой задачи плагин переименовывает в «КОД — Название». Поэтому код всегда
виден в заголовке чата: если сомневаешься, посмотри название текущей сессии.

Кнопка **Commit** в поле ввода сама подставляет код задачи, если чат привязан
к задаче. Если код не подставился — возьми его из названия чата.

После законченной задачи — коммит, и в сообщении **первым идёт код задачи**:

```
PRJ-1: перенос коробок
```

Плагин связывает коммит с задачей по коду в сообщении, поэтому формат важен.

После коммита обнови файл `.workspace/commits.json`:

```json
{
  "commits": [
    {
      "sha": "a1b2c3d",
      "date": "2026-11-09T10:00:00Z",
      "author": "Pashk",
      "message": "PRJ-1: перенос коробок",
      "branch": "main",
      "files": [
        { "path": "game/modules/100_goods_carry/logic.gd", "add": 42, "del": 3 }
      ]
    }
  ]
}
```

Пользователь нажмёт **«Импорт коммитов»** на вкладке «Коммиты» — история появится
на доске. Откат делает `git revert <sha>`, а не `reset`.

## Чего не делать

- Не дублировать задачи: сначала прочитай существующий файл.
- Не менять `id` у существующей задачи.
- Не требовать кодов, если пользователь их не любит.
- Не писать задачи просто текстом в чат — только файл.
