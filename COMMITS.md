# Как подключить историю коммитов

Плагин не запускает `git` сам — он читает файл, который готовит агент.
Эта страница объясняет, где файл лежит, какого он формата и что делать,
если история не появляется.

## Важно: пока нет первого коммита, файла нет

Плагин файл **не создаёт** — он только читает. Поэтому на свежем проекте:

- `.workspace/commits.json` отсутствует;
- вкладка «Коммиты» пустая;
- кнопка «Обновить» сообщает, что прочитать файл не удалось.

**Это нормально.** Файл появляется после первого коммита, когда агент его
запишет: нажмите **Commit** в поле ввода или попросите «сделай первый коммит и
обнови `.workspace/commits.json`».

Если коммитов ещё нет, а хочется увидеть пустую доску вместо ошибки — попросите
агента создать файл с пустым массивом:

```json
{ "branch": "main", "ahead": 0, "behind": 0, "dirty": false, "status": [], "commits": [] }
```

## Где лежит файл

В корне проекта, рядом с `.git`:

```
мой-проект/
  .git/
  .workspace/
    commits.json      ← история коммитов
    tasks.json        ← задачи доски (необязательно, импортируются вручную)
  src/
  README.md
```

- Папка `.workspace` — служебная, создаётся автоматически при первом импорте
  или когда агент её создаёт.
- Файл `commits.json` — единственный источник истории для вкладки «Коммиты».

## Как плагин его читает

Три способа, все ведут к одному результату:

1. **Автоматически.** Пока открыта вкладка «Коммиты», плагин перечитывает файл
   раз в 5 секунд. Если файл изменился — список и статус обновляются сами.
2. **Кнопкой «Обновить».** Читает файл сразу, без ожидания. Рядом появляется
   пометка: «Обновлено» или код ошибки.
3. **Импортом.** Кнопка «Импорт» принимает JSON через выбор файла — на случай,
   если автоматическое чтение недоступно.

Поэтому порядок такой: агент закоммитил → переписал `.workspace/commits.json` →
через несколько секунд плагин это увидел.

## Почему файл, а не git напрямую

Браузерная часть плагина не имеет доступа к диску и не может выполнять команды.
Файл — единственный канал: агент умеет и `git`, и запись файлов.

## Формат файла

```json
{
  "branch": "main",
  "ahead": 0,
  "behind": 0,
  "dirty": false,
  "status": [],
  "commits": [
    {
      "sha": "a1b2c3d4e5f6",
      "date": "2026-11-09T10:15:00Z",
      "author": "Pashk",
      "message": "PRJ-1: перенос коробок",
      "branch": "main",
      "diff": "@@ -1,3 +1,5 @@\n-old line\n+new line",
      "files": [
        { "path": "game/modules/100_goods_carry/logic.gd", "add": 42, "del": 3 },
        { "path": "game/modules/100_goods_carry/view.gd", "add": 18, "del": 0 }
      ]
    }
  ]
}
```

### Поля верхнего уровня

| Поле | Тип | Обязательно | Что значит |
|---|---|---|---|
| `branch` | строка | нет | Текущая ветка. Показывается в шапке вкладки |
| `ahead` | число | нет | На сколько коммитов впереди origin |
| `behind` | число | нет | На сколько отстаём от origin |
| `dirty` | true/false | нет | Есть ли незакоммиченные изменения |
| `status` | массив | нет | Список изменённых файлов для плашки «есть изменения» |
| `commits` | массив | **да** | Сама история, новые коммиты сверху |

### Поле `status`

Каждый элемент — либо строка с путём, либо объект:

```json
{ "status": "M", "path": "src/main.js" }
```

`status` — как в `git status --porcelain`: `M` изменён, `A` добавлен,
`D` удалён, `??` не отслеживается.

### Поля коммита

| Поле | Тип | Обязательно | Что значит |
|---|---|---|---|
| `sha` | строка | **да** | Полный или короткий хеш |
| `message` | строка | **да** | Сообщение. Первая строка — заголовок в карточке |
| `date` | ISO-строка | нет | Дата коммита |
| `author` | строка | нет | Имя автора |
| `branch` | строка | нет | Ветка коммита; по ней строится цветная дорожка |
| `files` | массив | нет | Изменённые файлы: `{ "path", "add", "del" }` |
| `diff` | строка | нет | Фрагмент diff. Показывается первыми 8 строками, дальше — «Показать полностью» |

`add` и `del` — число добавленных и удалённых строк (0, если бинарный файл).

### Связь с задачами

Если в сообщении коммита есть код задачи (`PRJ-1`, `M_001` — любой), плагин
найдёт задачу на доске по коду. Тогда на карточке коммита появится кнопка
«Задача», а в окне задачи — блок «Коммиты».

Код ищется простым вхождением подстроки в `message`, поэтому формат сообщения
важен: код должен быть в тексте.

## Как агенту собрать файл

Агенту достаточно трёх команд:

```bash
git status --porcelain            # для dirty и status
git log -n 50 --format='%H|%an|%aI|%s'   # шапки коммитов
git show --numstat --format='' <sha>     # файлы и +/−
```

Дальше он собирает JSON и записывает в `.workspace/commits.json`.
Плагин подхватит сам.

Проще всего попросить агента так: **«обнови `.workspace/commits.json`»** —
или нажать кнопку **Commit**, если установлен плагин Composer Actions:
она делает коммит и обновляет файл.

## Стоит ли коммитить сам файл

Обычно нет: это кеш, его легко пересобрать. Добавьте в `.gitignore`:

```gitignore
.workspace/
```

Если хотите, чтобы история ехала вместе с репозиторием — уберите строку
и коммитьте файл вручную.

## Если история не появляется

Пометка рядом с кнопкой «Обновить» говорит, что именно не так:

| Пометка | Причина | Что делать |
|---|---|---|
| `no-file-api` | Плагин не получил доступ к файловому сервису | Перезагрузить Harness; проверить, что панель открыта в сессии проекта |
| `no-session` | Нет ни одной сессии проекта | Открыть чат в этом проекте и повторить |
| `empty-file` | Файл прочитан, но пустой | Проверить, что агент записал содержимое |
| `read-failed` | Файл не читается | Проверить путь и права |
| `Обновлено` | Всё хорошо | — |

Частые причины: файл лежит не в корне проекта, битый JSON (лишняя запятая),
или агент записал файл в другую папку.

## Быстрая проверка вручную

1. Открыть `.workspace/commits.json` в редакторе.
2. Убедиться, что это валидный JSON (без комментариев и висячих запятых).
3. В Harness: Work Space → «Коммиты» → «Обновить».
4. Если пометка «Обновлено», а список пуст — значит `commits` пустой массив.
